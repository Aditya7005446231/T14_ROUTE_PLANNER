# T14. Multi-Stop Route Planner [Travel]

The T14 Multi-Stop Route Planner equips the autonomous agent with two core tools: `get_distance` and `order_stops`. The `get_distance` tool queries a mock driving distance dataset covering major Indian tourist cities (Delhi, Agra, Jaipur, Chandigarh, and Amritsar) with symmetric distance resolution, allowing the agent to evaluate pairwise road travel costs. Once the agent determines the shortest visiting sequence, it calls `order_stops` to save and commit the structured route order into session state, ensuring plan decisions are persisted beyond plain text answers.

Conversational memory and state persistence are implemented using LangGraph's `MemorySaver` checkpointer combined with a dedicated session state array in `tools.py`. The `MemorySaver` checkpointer retains thread-level conversation history across multi-turn interactions, enabling the agent to remember previously visited cities, user constraints, and prior route recommendations without requiring the user to restate details. Simultaneously, the `order_stops` tool appends committed itineraries directly to `SAVED_ROUTES`, decoupling conversational context from structured application state.

During initial testing, an honest failure occurred when the LLM attempted to invoke `order_stops` by passing a formatted string (such as `"Delhi -> Agra -> Jaipur"`) instead of a strict Python list of strings (`["Delhi", "Agra", "Jaipur"]`), causing validation errors in tool schema parsing. This issue was resolved by implementing flexible input type handling inside `order_stops` using `Union[List[str], str]` alongside string parsing logic that converts delimiter-separated strings into normalized lists, making tool execution resilient to varying LLM output formats.
